contributing

Open contributions — from humans.

Block loads into other people’s processes. A bad patch crashes a viewer mid-session. Own the diff, test it, and keep PRs focused.

Read the AI policy Full guide on GitHub

Ground rules

  1. Human authorship. No Copilot / ChatGPT / Claude / Cursor Agent / Gemini paste-jobs — disclosed or not. See AI policy.
  2. Honest compatibility. Only claim a viewer you launched with your build.
  3. Licence. Code lands under BSD-2-Clause. Update notices when you vendor upstream.
  4. Focused PRs. One concern when possible. No drive-by dependency dumps.
  5. Brand. Lime signal #D4FF3F, lockups in brand/ — do not invent a second look.

Before you open a PR

  • Branch from main
  • Exercise the path you changed — viewer + Shift+B for overlay work
  • Paste log text, not screenshots of screenshots
  • Fill the PR template, including the human-authored checkbox
  • Do not commit build/, build-win/, or viewer logs

What GitHub checks on every PR

  • Human authorship gate — PR body must confirm you wrote the patch (template checklist)
  • AI heuristic scan — flags common LLM watermarks in added lines
  • Linux Vulkan build — Meson compile so the layer keeps building
  • Doc path sanity — required docs and site files still exist

A green CI check does not replace “I ran Shift+B on my viewer.” False-positive AI heuristics: explain in the PR and ask a maintainer.
